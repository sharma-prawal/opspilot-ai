# OpsPilot AI v0.7.0 — Incident Forensics Lab Visual Identity

v0.7.0 replaces the generic AI dashboard aesthetic with a distinctive, purpose-built product experience: the **Incident Forensics Lab**. Designed for SREs, incident commanders, and forensic investigators, the new interface treats autonomous incident response as an evidence-grounded scientific inquiry.

Base: published v0.6.0 (`main` at `011853f`). All backend safety guarantees, deterministic evaluation suites, and MCP tool protocols remain intact.

## What is new

### 1. Incident Forensics Lab Visual Direction
- **Archival Editorial Identity:** Warm ivory paper canvas (`#FBFBF8`), editorial serif typography (Newsreader / Playfair / Georgia fallback), crisp mono metrics (JetBrains Mono), and warm amber/crimson forensic accents replacing generic dark navy cards.
- **Evidence Dossier Architecture:** Reorganized incident views around structured case files: exhibit tags, chronological cross-examination chains, and forensic provenance stamps.
- **Responsive & Accessible:** Fully responsive investigation workbench across desktop, tablet, and mobile (390px viewport) with readable typography, zero horizontal overflow, and touch-friendly controls.

### 2. Synchronized Incident Time Ribbon
- **Chronological Scrubbing:** A synchronized horizontal event timeline tracking incident onset, tool calls, hypothesis formulation, approval gates, and verified recovery.
- **Flexible Event Inspection:** Horizontal scrolling with flex-shrink protection and right padding preventing event clipping. Selecting a timeline event scrolls directly to corresponding evidence exhibits.

### 3. Interactive Causal Explorer
- **Relational Highlighting:** Selecting a root-cause hypothesis highlights connected supporting and contradicting evidence exhibits and vice versa.
- **Direct Citation Provenance:** One-click navigation from cited evidence directly to raw logs, metrics CSV lines, trace spans, and PostgreSQL RRF knowledge chunks.

### 4. Truth-in-UI & Presentation Consistency
- **Separation of Concerns:** Clear presentation-layer distinction between historical/external incident status (`External: {status} (unverified)`), analysis completion (`Analysis complete (read-only)`), and OpsPilot-verified recovery.
- **Read-Only Mode Enforcement:** Uploaded file analysis and connected Loki/Prometheus telemetry modes strictly omit remediation controls and never claim live recovery.
- **Actual Runtime Model Attribution:** Model labels dynamically sourced from runtime configuration (`qwen3.5:9b-q4_K_M` and `qwen3-embedding:0.6b`), accompanied by clear labels marking LLM confidence estimates as uncalibrated.
- **Scenario Fidelity:** Screenshot fixtures and documentation precisely aligned with documented scenario rules (e.g., INC-002 capacity gate D25 blocking connection pool expansion in favor of rollback).

### 5. Verification & Testing
- New automated Playwright smoke tests verifying primary intake headings, mode switching, navigation, and absence of crash error boundaries.
- 50/50 unit tests, 0 lint warnings, 0 type errors, 27/27 static/dynamic Next.js routes compiled.
