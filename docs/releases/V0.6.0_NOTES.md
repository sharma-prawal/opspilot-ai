# OpsPilot AI v0.6.0 — Connected Observability

v0.6.0 connects OpsPilot to the observability you already run. Point it at **Grafana Loki** and **Prometheus**, pick
a service, an incident window and approved query templates, preview what comes back, and run the same evidence-cited
LangGraph investigation with your local model. Like uploaded files, connected incidents are **read-only**: OpsPilot
suggests remediation but never executes it, and never claims recovery from historical data. It remains an
experimental, local-first POC.

Base: published v0.5.0 (`main` at `7677360`). Decisions: D109–D115 in
[DECISIONS.md](../DECISIONS.md). Full guide: [CONNECTORS.md](../integrations/CONNECTORS.md).

## What is new

### Connectors (implemented)
- **Grafana Loki:** logs via `GET /loki/api/v1/query_range` (Unix-nanosecond window, `direction=backward`,
  limit); optional `X-Scope-OrgID` tenant.
- **Prometheus:** metrics via `GET /api/v1/query_range` (Unix-second window, step about window/240, never below 15 s).
- **Planned, not implemented:** Azure Monitor, Datadog, CloudWatch and custom adapters. The `TelemetryConnector`
  contract describes what an adapter must do.

### Investigate with connected telemetry (`/incidents/new?source=connected`)
- Connector cards with **Test connection**. States: connected, authentication failed, unavailable, error, not
  configured.
- **Find services in this window** lists the values of the configured service label.
- **Approved templates:**
  - Loki: errors and warnings, start-up/shutdown/config lines, all lines;
  - Prometheus: 5xx ratio, p95 latency, request rate;
  - more from `TELEMETRY_TEMPLATES_FILE`.
  - You never type a query.
- **Preview:**
  - counts and per-query status (ok, no data, auth error, unavailable, query rejected, truncated) with the
    rendered query;
  - which services each signal was collected for, coverage warnings, and sample records with their query source.
- **Create incident & start analysis** stores the results as a snapshot and starts the investigation.
- **Integrations** shows each connector's live state, endpoint, auth mode, templates and limits.

### Evidence and provenance
- Records use the same contracts as uploads. Each keeps its original timestamp, unit, labels, and a source reference
  such as `loki/errors_warnings/payment-service:entry 37` or `prometheus/http_5xx_ratio/checkout-api:point 12`.
- The report adds a "Telemetry queries (provenance)" table, connected-specific next steps and a Markdown download.
- The investigation reads only the stored snapshot (tool server `opspilot-connected-telemetry`), never the backend.
  Runbook RAG stays separate.
- **Unknown stays unknown.** Change history, traces and live state are not part of Loki/Prometheus, and a signal
  whose queries failed is unavailable for that service. None of these is reported as healthy. The RCA prompt says so
  explicitly when change history could not be read (D115).

### Security
- **Destinations:** only the configured URLs, via GET to allowlisted read endpoints. No redirects, no proxy/netrc,
  timeouts, a 6 h window, at most 40 queries, line, series and response-size limits.
- **Requests** carry IDs and a window. Query or URL fields are rejected.
- **Credentials:**
  - environment only;
  - never returned to the browser;
  - https unless loopback;
  - scrubbed from errors.
- Connector actions are operator-only. A backend 401 is shown as a per-query authentication error, never as a
  sign-out.

### Local test setup
- `make telemetry-up` starts Loki 3.5.0 (multi-tenant) and Prometheus 3.5.0 on 127.0.0.1, with data in tmpfs.
  They hold a synthetic incident: payment-service 2.14.0 shrinks its database pool, and checkout payments time out.
- `make telemetry-down` removes them.

### Other changes
- Migration `0011`: incident `evidence_source='connector'` and `ops.uploaded_datasets.queries`. Run `make migrate`.
- **Delete snapshot** and `make uploads-purge` cover connected incidents.
- `scripts/e2e-api.sh` accepts `E2E_TELEMETRY=1`.

## Verification (development testing)
- Unit tests for configuration validation, templates and injection, normalization and provenance, limits, every
  error kind, redaction and "GET only to allowlisted paths".
- Graph tests for a read-only cited analysis and for failed metrics leaving impact unknown.
- API tests for listing without secrets, tests, preview, validation, investigation without action requests, and
  deletion.
- BFF route tests.
- Live tests against the local Loki/Prometheus.
- Playwright: the connected journey plus the existing simulator, upload and auth specs.
- Demonstrated with `qwen3:8b` and `qwen3.5:9b-q4_K_M` (one run each; see PROGRESS.md).

## Limitations
- Tested only against local containers with synthetic data. Thanos, Mimir and VictoriaMetrics were not tested.
- Built-in PromQL templates assume `http_requests_total` / `http_request_duration_seconds`. Other schemas need a
  templates file.
- Service names must be lower-case slugs matching the label values.
- A snapshot is historical. It cannot show the current state, and change history must come from elsewhere.
- In the demonstration, `qwen3:8b` identified the mechanism (pool exhaustion) but not the specific trigger (pool size
  reduced), which the telemetry shows. Hypothesis confidence is model-estimated and uncalibrated.
- OpsPilot cannot verify that a credential is read-only. Use read-only credentials.
- The official evaluation (`docs/evaluation/BASELINE.md`) still reports the v0.2.1 simulator run.

## Upgrade notes
Run `make migrate`. Connectors are off unless `LOKI_URL` / `PROMETHEUS_URL` are set (see `.env.example`). Existing
simulator and uploaded incidents behave as before.
