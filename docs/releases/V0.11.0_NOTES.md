# OpsPilot AI v0.11.0 — AWS CloudWatch Logs & Metrics

Approved release of `feature/aws-cloudwatch-v0.11.0` (implementation `be52b76`, RCA correctness pass `a9af6e0`,
screenshots `dffa55e`), merged into `main` on top of v0.10.0 (`2154211`) with a non-rewriting merge commit.

> **No real AWS account was used for testing.** Everything below was verified only against a synthetic CloudWatch
> protocol fixture (`scripts/cloudwatch_fixture.py`) driven by the real AWS SDK (boto3/botocore 1.44). **AWS
> authentication compatibility, IAM behaviour, live Logs Insights query syntax, quotas and actual scan costs are not
> verified.** The live-verification procedure is in [AWS_CLOUDWATCH.md](../integrations/AWS_CLOUDWATCH.md#optional-live-verification).

## At a glance

- **New:** AWS CloudWatch is an optional, backend-configured, **strictly read-only evidence provider** alongside
  Loki, Prometheus, Datadog and Azure Monitor. It feeds the existing frozen-snapshot LangGraph investigation; there is no
  AWS-specific agent or pipeline and no AWS write or remediation capability anywhere.
- **Truthfulness:** better evidence grouping and source citations; deterministic warnings on unsupported RCA claims.
  The RCA is still written by a local model: warnings annotate it, they do not make it correct.
- **No database migration.** New dependency: `boto3`, loaded only when `CLOUDWATCH_ENABLED=true`.

## CloudWatch capabilities

- **Logs — CloudWatch Logs Insights (QL).**
  - Six built-in templates: errors, warning/error chronology, timeouts and dependency failures, start-up / version /
    configuration indicators, correlated failures, and a log-based error count per time bin.
  - Queries run only over the log groups mapped to each service.
  - JSON and plain-text logs both work. Timestamps, log group, stream, `@ptr` and correlation IDs are kept; credential-like
    values are redacted.
- **Metrics — `GetMetricData`.**
  - Load balancers: target 5xx, request count, target response time p95 and unhealthy targets.
  - ECS services: CPU and memory.
  - Lambda functions: errors, invocations, duration p95 and throttles.
  - Up to 10 configured custom metrics per service.
  - One statistic per template, a period that respects CloudWatch's retention resolutions, and the unit AWS documents
    (the API returns none). Periods without a datapoint stay absent, never zero.
- **Configured log-group and service mappings.** `CLOUDWATCH_RESOURCES_FILE` maps each OpsPilot service to its exact
  log groups and metric dimensions, and it is the allowlist.
  - Services are never inferred from resource names, and nothing is enumerated account-wide.
  - A template whose resource is not mapped is recorded as *not queried* and never sent.
  - Shared log groups need a recorded `service_field`.
- **Explicit AWS authentication** (`CLOUDWATCH_AUTH_MODE`):
  - `profile`: named profile, including IAM Identity Center/SSO. OpsPilot never logs in; an expired session is
    reported.
  - `instance_role`: ECS task role, EKS Pod Identity / IRSA, EC2 instance profile.
  - `access_keys`: explicit keys, temporary ones preferred.

  Each mode uses only its own credential source, with no fallback to environment keys or instance metadata. An
  unrelated `AWS_PROFILE` is ignored. Optional extras are one assumed read-only role and an expected-account check.
  Nothing contacts AWS at import or start-up. Only the commercial partition is supported. Endpoint overrides are
  ignored, and every client's regional endpoint is verified.
- **Bounded asynchronous queries and cancellation.** `StartQuery` is followed by bounded `GetQueryResults` polling:
  - at most 3 queries in flight per connector;
  - at most 40 polls or 60 s per query;
  - at most 500 events per query (configurable, maximum 2,000);
  - at most 10 log groups per service;
  - a 6 h window.

  A query that does not finish, or whose request is cancelled, is stopped with `StopQuery` for **its own query ID
  only**. Rows already returned are kept and marked partial, and a failed stop is recorded.
- **IAM permissions and cost.** The minimum actions are `logs:StartQuery`, `logs:GetQueryResults` (scoped to the
  approved log-group ARNs), `logs:StopQuery`, `logs:DescribeLogGroups` and `cloudwatch:GetMetricData`. Example policy:
  `infra/cloudwatch/iam-readonly-policy.example.json`.
  - Logs Insights is **billed by scanned volume**: OpsPilot records the scan statistics of every query but cannot cap
    cost.
  - The connection test runs one tiny Logs Insights query per configured log group. Read-only is not free.
- **Frozen evidence snapshots and read-only RCA.**
  - Order: collection → normalization → preview → frozen snapshot → the unchanged LangGraph investigation. AWS is never
    contacted during an investigation.
  - Provenance records region, account, log groups, Logs Insights query ID, status, polls and scan statistics, or the
    metric definitions.
  - Reports cite `cloudwatch/<template>/<service>:entry|point N`. Export and dataset deletion work as for the other
    connectors.
- **Web (Visual Experience 2.0 kept).**
  - Integrations catalogue (now *implemented*), capability matrix and connector panel.
  - Connected intake: region, account, per-log-group *readable / access denied / not found*, cost note, fixture demo
    incident, query provenance.
  - AWS provenance on the incident page.
  - `CLOUDWATCH_*` and `AWS_*` never reach the web process.

## Evidence quality and RCA warnings

- **Evidence grouping (D144).** Repeated log lines that differ only by a request, trace or correlation ID value, or an
  AWS X-Ray trace ID, now form one pattern.
  - Before, each such line was its own one-off pattern, and the fixture's dominant error (143 occurrences) never reached
    the model. Grouping ignores only the ID values; the stored line is unchanged.
  - Simulator clustering is byte-identical, so the evaluation baseline is unaffected.
- **Source citation.** Observed start-up and configuration lines are shown by their recorded message with their source
  reference: in the prompt digest, the report's *Observed events* row and the change-indicator notes. They are still
  labelled log indicators, not a verified deployment history or proof of cause.
- **Deterministic claim warnings (D143, D144)** for read-only RCAs; simulator RCAs are not annotated. A note is added
  when the RCA:
  - names a version number or quoted identifier that appears nowhere in the collected evidence;
  - claims a deployment or configuration change without citing any change evidence;
  - states a cause as established;
  - calls a start-up or configuration log line a deployment;
  - says "ongoing" (anchored to the end of the snapshot);
  - suggests `restart_service` while hypothesis 1 names a persistent setting or limit. The note reads: "Restarting a
    service generally reloads its persisted configuration and may not resolve the underlying configuration problem."
- **Recommendations may remain incorrect despite the warnings.** The checks are English pattern heuristics. The model's
  text is never edited, re-ranked or removed, and suggested actions are never executed.

  Example from the final real-model run: the suggested restart claims it would "restore db.pool.max_size to 40". The
  limitation note says that a restart reloads the persisted configuration and may not fix it.

## Not verified / limitations

- **No real AWS account**: AWS authentication, IAM resource scoping (the example policy follows the Service
  Authorization Reference), acceptance of the Logs Insights templates by the live service, quotas and scan costs.
- One region and one account per API process; no cross-account observability, GovCloud, China or ISO partitions.
- Logs Insights QL only and built-in templates only; the keyword regular expressions are English.
- No CloudTrail or AWS Config change history, X-Ray traces, alarms, live state or console deep links; change history
  stays unknown.
- The connection test runs small billed queries; `StopQuery` permission cannot be probed.
- The RCA remains model-generated: warnings are heuristic safeguards and cannot catch every unsupported claim.
