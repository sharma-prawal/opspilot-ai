# OpsPilot AI v0.2.1 — release notes (draft, unreleased)

v0.2.1 is a hardening release on top of v0.2.0 (`9ec857c`). It remediates the independent Codex audit of
v0.2.0: 4 High, 8 Medium and 1 Low verified findings, and 3 suspected risks. It adds no new incident scenarios or
product features.

Evidence for every item (reproduction, root cause, change, tests, remaining risk):
[`docs/audits/PHASE_C0_REMEDIATION.md`](../audits/PHASE_C0_REMEDIATION.md).

> Status: **draft**. Not tagged or published. The branch `hardening/phase-c0` is awaiting independent
> verification.

## Security

- **Authenticated operator UI.** The web BFF no longer attaches operator credentials to any same-origin POST.
  - Sign-in issues a signed, HttpOnly, SameSite=Strict session.
  - Mutations require same-origin, a session-bound CSRF token, JSON and the operator role.
  - Decision identity comes from the session.
  - Missing configuration fails closed.
- **Every backend mutation requires the operator token**, so callers cannot bypass the BFF.
- **No credentials in records.** A central redaction policy covers tool-call history, workflow events, API
  responses, structured logs and the BFF relay. Spent approval tokens are cleared from workflow state.
  `opspilot sanitize-secrets` (dry run by default) handles records written before the upgrade.
- **Cancellation cannot race execution.** The action server claims an approved action under a row lock before any
  effect. Cancellation revokes unclaimed approvals first and is refused once execution has been claimed.
- **Least-privilege MCP servers.**
  - Each server process gets a minimal environment: no `.env`, no operator token, no web secrets.
  - Each gets its own database role; the action server's role can change only an action request's status.
  - Provision the roles with `make db-roles`.

## Workflow reliability

- **Impact is `ongoing`, `recovered` or `unknown`.** Missing, failed or insufficient telemetry can no longer
  resolve an incident; `unknown` blocks remediation and escalates. An explicit escalation always outranks
  "no action required".
- **Approval decisions survive crashes.** A transactional outbox, at-least-once delivery, idempotent effects and
  start-up reconciliation are in place. Graceful shutdown records runs as resumable (`interrupted`), not
  `cancelled`.
- **Complete recovery verification.** Every required condition is checked, or reported as not checked within an
  explicit budget. Metric-specific health semantics and action postconditions apply, and there is a new
  `verification_incomplete` outcome.
- **Uncertain diagnoses are not proposed for approval.** Plans are withheld when confidence is low, escalation is
  requested, the top hypotheses compete with disjoint evidence, or the investigation budget ran out.
- **One active investigation per incident, enforced by the database.** A DB execution lease prevents two API
  processes from running one workflow.
- **Bounded resources.** Embedding requests are concurrency-bounded, and the work queue is bounded: excess starts
  receive HTTP 429 before anything is written.

## RAG and citation integrity

- Document lifecycle changes (status, version) are tracked without re-embedding.
- Current guidance outranks unreviewed and superseded material *before* top-k truncation.
- Citations are verifiable snapshots: full passage, SHA-256, document version, lifecycle status and retrieval
  time. An RCA remains reconstructable after its sources are re-ingested.
- Retrieval degradation (keyword-only fallback) is reported through MCP to the agent.

## Evaluation corrections

- Plan scoring checks order, undeclared extra actions, attempted (including failed) actions and forbidden
  attempts independently. A forbidden action can no longer score as an acceptable plan.
- A new agent-path retrieval benchmark measures the passages the agent actually supplies to its RCA prompt, next
  to the document-level benchmark.
- A resource-measurement suite covers embedding bursts, model latency and Ollama memory.
- The Phase B evaluation artifacts are preserved verbatim under `datasets/evaluation/history/`.

## Testing

- 180 deterministic tests (unit, integration and security, on the dedicated `opspilot_test` database), 30 web
  unit tests, 3 live-model tests, and browser E2E.
- New regression suites:
  - crash-boundary decision delivery;
  - cancellation races, with a two-sided timing sweep;
  - concurrent creation across two DB engines;
  - DB-role privileges, executed as each role;
  - sentinel-token leak scans across all tables and endpoints;
  - citation reconstruction after re-ingestion;
  - MCP degradation contract.
- **Isolated E2E.** `make e2e` starts its own API (forced onto `opspilot_test`) and web server, and verifies the
  browser → BFF → API → database identity before any mutation. It runs safely beside `make dev`.

## Upgrade notes

1. `make migrate`: migrations 0004 (decision outbox) and 0005 (single-active-investigation index, execution lease
   columns). Both are additive. 0005 refuses to run, changing nothing, if an incident already has two active
   investigations.
2. Add `OPSPILOT_WEB_SESSION_SECRET`, `OPSPILOT_WEB_OPERATOR_PASSPHRASE`, `MCP_READ_DB_PASSWORD` and
   `MCP_ACTIONS_DB_PASSWORD` to `.env` (`scripts/bootstrap.sh` adds missing ones), then run `make db-roles`.
3. Restart the API and web (`make stop && make dev`) and sign in at `/login`.
4. Optional: run `uv run opspilot sanitize-secrets` (dry run) to find approval tokens stored by earlier versions.
   `--apply` redacts their values in place; back them up first (see the remediation record).

## Known limitations

- **INC-002 end-to-end regression.**
  - In the release evaluation INC-002 was mitigated in 1 of 2 trials (1 of 5 in a supplementary run), against 2 of
    2 in v0.2.0.
  - A controlled ablation attributes this to the corrected lifecycle ranking changing the model's context. With the
    old ranking: 5 of 5.
  - The failing runs are safe: the model's unsafe and invalid steps were blocked, nothing executed, and the
    incident was escalated.
  - The ranking was not reverted, and prompts were not tuned, to recover a known scenario.
- The model still misattributes the cause in NEG-002 and proposes actions in every negative scenario. The safety
  gates, not the model, prevent execution.
- One shared passphrase per role, not per-user identity (OIDC planned). There is no operator override for
  withheld plans.
- MCP servers run as the same OS user, so DB roles limit their connections but not file access.
- LangGraph checkpoint history retains past approval steps' short-lived, action-bound tokens.
- Cross-process cancellation takes effect at the next boundary. Resource bounds are per process.
- Single author for scenarios and labels; the safety gates were designed after observing failures on these
  scenarios.
