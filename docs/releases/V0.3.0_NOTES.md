# OpsPilot AI v0.3.0 — Modern Operator Console, Interactive Architecture & Extensibility Guide

OpsPilot AI v0.3.0 delivers a complete product-experience transformation: elevating OpsPilot from a functional engineering POC into an intuitive, polished, and source-agnostic AI incident-response platform.

All changes are strictly focused on operator experience, interactive visualization, and developer documentation. The underlying deterministic safety architecture, invariant safety gates, and local execution boundaries are fully preserved.

---

## What is new in v0.3.0

### 1. Premium Dark-First Operator Console
- **Cohesive Design System**: Built with Next.js 16 Turbopack, React 19, TypeScript, and Tailwind CSS v4.
- **Overview Dashboard (`/`)**: Real incident and investigation summaries, synthetic fault scenario launch cards, and runtime dependency health indicators.
- **Incident Command Center (`/investigations/[id]`)**:
  - 12-stage LangGraph workflow stepper displaying real-time execution progress.
  - Root-cause hypothesis ranking grounded in evidence, with transparent model-estimated confidence indicators.
  - Distinct visual separation for model proposals blocked by deterministic safety gates before reaching human review.
  - Cryptographically bound Human-in-the-Loop (HITL) approval cards for safe sandbox remediation.
  - Affirmative recovery verification with pre- and post-action metric comparisons.
  - Rendered markdown postmortem RCA reports with evidence citations.

### 2. Interactive Architecture & Workflow Explorer (`/architecture`)
- Interactive graph canvas powered by `@xyflow/react` with auto-fit, minimap, controls, and screen-reader accessible hierarchy mode:
  - **Diagram A (System Architecture)**: Component topology connecting the Next.js Operator UI, BFF proxy, FastAPI runner, LangGraph orchestrator, native Ollama inference, PostgreSQL + pgvector datastore, MCP stdio read/action servers, and the deterministic safety boundary.
  - **Diagram B (Agent Workflow Graph)**: Real execution graph with conditional branching for supervisor planning, evidence gathering, RCA generation, safety policy validation, human approval interrupt, sandbox action execution, recovery verification, and escalation.
  - **Diagram C (Hybrid RAG Pipeline)**: Document ingestion, chunking, pgvector dense retrieval (HNSW cosine similarity) + PostgreSQL full-text search (GIN tsvector / `ts_rank_cd`), fused via Reciprocal Rank Fusion (RRF), with graceful degradation to keyword-only search when embedding services are down.
  - **Diagram D (Evidence Ingestion & Extensibility)**: Source-agnostic architecture showing logs, metrics, traces, deployment changes, dependencies, and runbooks across Demo, Offline, and Connected modes.

### 3. Source-Agnostic Integrations Catalog (`/integrations`)
- Interactive integration blueprints categorizing evidence sources across three modes:
  - **Demo Mode**: Built-in synthetic fault simulator (INC-001, INC-002, INC-003, NEG-001, NEG-002, NEG-003).
  - **Offline / File Mode**: Metric CSV/JSON exports, log dumps, OpenTelemetry trace snapshots, and runbook markdown.
  - **Connected Observability Mode**: Prometheus, Loki, OpenTelemetry Collector, AWS CloudWatch, Datadog, GitHub Actions, Azure DevOps, and custom HTTP/stdio adapters.
- Explicit implementation status badges (`Implemented`, `Requires Adapter`, `Planned`) preserving architectural honesty.

### 4. In-App Developer Guide & Safety Center
- **Developer Guide (`/guide`)**: Interactive 12-step local setup, verification commands, and system concepts.
- **Safety Center (`/safety`)**: Dedicated specification of the Seven Invariant Safety Gates and the human approval security boundary.
