# OpsPilot AI v0.4.0 — Agent Reasoning, Configurable Local Models and Two Safety-Gate Fixes

v0.4.0 improves the investigation agent's own reasoning, makes the local model a configuration choice, and closes
two safety-gate gaps found while testing. It is still an experimental, local-first POC: remediation acts only on
the deterministic simulator, and every state-changing step still needs signed human approval.

Base: published v0.3.0 (`main` at `1305d1e`). Details and data: [MODEL_COMPARISON_V0.4.md](../evaluation/MODEL_COMPARISON_V0.4.md).
Decisions: D96–D102 in [DECISIONS.md](../DECISIONS.md).

## What is new

### Configurable local models
- The investigation model is `LLM_MODEL` in `.env`; nothing in the code or UI names a model. The UI shows the active
  model and its options (overview, investigation header, architecture, integrations, guide).
- **Preferred: `qwen3.5:9b-q4_K_M`** (new default in `.env.example`); **fallback: `qwen3:8b`**. Embeddings unchanged
  (`qwen3-embedding:0.6b`).
- `uv run opspilot models [--model TAG] [--probe]` reports capabilities, runner and quantization, and makes one
  schema-constrained call through the real adapter. `make doctor` now checks structured output, not only text.
- On Apple Silicon the plain `qwen3.5:9b` tag resolves to an MLX build for which Ollama 0.40.14 answers
  structured-output requests with HTTP 501. Use the GGUF tag `qwen3.5:9b-q4_K_M`. The chat adapter now fails fast on
  such non-retryable responses.

### Opt-in model downloads
- `make bootstrap` no longer downloads models. If a configured model is missing it stops and explains.
- `make models` (or `make bootstrap ARGS=--pull-models`) downloads `LLM_MODEL` and `EMBEDDING_MODEL` (~7.3 GB with
  the defaults) and probes them. Existing `.env` files are never changed.

### Agent reasoning
Diagnosed from the published qwen3:8b traces, where the deciding facts were in the prompt but ignored:
- **Evidence digest**: the RCA prompt opens with key findings computed in code (impact state, change correlation,
  which dependency the errors name and whether it changed, queue state, missing evidence).
- **Explicit decision** (remediate / no action needed / escalate) before the plan, with escalation defined as a
  hand-over, not urgency.
- **Decode-time constraints**: cited evidence IDs and plan identifiers are restricted to observed values, and only
  catalogue actions the evidence makes applicable are offered. Fabricated IDs are no longer possible.

### Safety-gate corrections
- **Resume only paused consumers** (D100): `resume_consumer` needs a validated pause earlier in the same plan, or
  evidence that the consumer is paused. A running consumer is refused; missing state is unknown and refused.
- **No bypass of a rejected or ambiguous resolution** (D101): unresolved change ambiguity in the evidence withholds
  every step, and containment/recovery steps are dropped when their resolution step was rejected. A restart justified
  by its own evidence is still allowed.
- Approval tokens, the execution claim and all other gates are unchanged.

## Results (development testing, not a benchmark)

Six public synthetic scenarios, one trial each, reused while tuning; these numbers do not generalize to unseen
incidents.

| | qwen3:8b v0.3 | qwen3:8b v0.4 | qwen3.5:9b-q4_K_M v0.4 |
|---|---|---|---|
| Correct system outcome | 6/6 | 6/6 | 6/6 |
| Root cause correct | 3/4 | 4/4 | 4/4 |
| Model's own plan acceptable to the answer key | 2/6 | 3/6 | 6/6 |
| …and admitted unchanged by the gates | 2/6 | 3/6 | 5/6 |
| Model itself abstained/escalated on the 3 negative scenarios | 0/3 | 1/3 | 3/3 |
| Unsafe or forbidden actions executed | 0 | 0 | 0 |

How to read the two plan rows: "acceptable to the answer key" is the existing scorer comparing the model's plan with
each scenario's ground truth (required steps in order, extras only from a permitted list, nothing forbidden). "Admitted
unchanged" additionally requires that the safety gates rejected none of the steps. They differ for qwen3.5 on INC-003:
it proposed `rollback → quarantine → resume`; the answer key permits a resume of that consumer, but the consumer was
running and had not been paused, so the gate rejected the resume (the D100 correction). The incident was still
mitigated and verified recovered.

## Limitations

- **Development testing, not a benchmark.** Six public, self-authored synthetic scenarios, one trial each at
  temperature 0. The prompt changes and both safety corrections were developed on these same scenarios, so the
  results are not an unbiased estimate for unseen incidents. Held-out (C1) cases were not used.
- **Historical baseline.** The official evaluation in `docs/evaluation/BASELINE.md` and the README's headline gated
  numbers are still the v0.2.1 run (`qwen3:8b`, 13 runs over the same six scenarios). They were not regenerated for
  v0.4.0; the v0.4 numbers above come from supplementary runs (`opspilot-eval agent --out`) kept in
  `datasets/evaluation/history/v0.4-model-comparison/`.
- **Latency** on a shared laptop varied by up to about 65 % between identical runs; the two models are similar in
  speed.
- **Safety still comes from the system, not the model.** qwen3:8b relies on the gates more often than qwen3.5; with
  either model, human approval and the deterministic gates decide what runs. Remediation acts only on the simulator.
- **Model support** was verified on Apple Silicon with Ollama 0.40.14 only. Other quantizations or Ollama versions
  should be checked with `uv run opspilot models --probe`.

  (live); web unit tests 38 passed; `make build-web` succeeded; live-model tests 3/3 with `qwen3.5:9b-q4_K_M`.
- UI smoke test with `qwen3.5:9b-q4_K_M` selected: INC-001 through sign-in, evidence, RCA (correct cause, 98%),
  human approval, sandbox rollback and verified recovery (5/5 conditions, outcome `mitigated`); the UI showed the
  active model throughout.
- Not re-run: the official `make evaluate` baseline (`docs/evaluation/BASELINE.md` still reports v0.2.1) and the
  Playwright e2e suite.

## Upgrade notes

- Existing installs keep their `LLM_MODEL`. To switch: set `LLM_MODEL=qwen3.5:9b-q4_K_M`, run `make models`, restart
  the API.
- `make bootstrap` on a machine without the configured models now stops with instructions instead of downloading.
- Merging the separate `phase-c1` branch later will need two trivial append-conflict resolutions (`Makefile`,
  `docs/DECISIONS.md`); v0.4 decision IDs start at D96 to avoid clashing with phase-c1's D65–D95.
