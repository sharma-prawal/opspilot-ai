# OpsPilot AI v0.7.1 — Maintenance

v0.7.1 is a maintenance release on top of published v0.7.0 (`624ef7f`). It fixes how the local launcher starts the
web server and how the UI reports values it does not have. It changes no agent, evaluation, API or database
behaviour, and needs no migration.

**Status: released 2026-11-19 (tag `v0.7.1`), experimental, local-first.**

## Fixes

### Secure Next.js environment
`load_env` exports the whole repository-root `.env`, and the web server used to inherit all of it. That included
database and MCP role passwords and `ACTION_SIGNING_KEY`, none of which the web process uses. `make dev` and
`scripts/start.sh` now start the web server through `opspilot_shared.web_env`. It passes an explicit allowlist:
the BFF settings (`OPSPILOT_API_URL`, `OPERATOR_TOKEN`, `OPSPILOT_WEB_SESSION_SECRET`,
`OPSPILOT_WEB_OPERATOR_PASSPHRASE`, optional `OPSPILOT_WEB_VIEWER_PASSPHRASE` / `OPSPILOT_WEB_ORIGIN`), plus basic
process and Node variables. A backend denylist is a second check. Backend credentials, model settings and connector
settings no longer reach the Next.js process or anything it spawns (D116).

### Reliable detached startup
The launcher starts `next dev` from `apps/web` in its own session, with stdin closed and output in `.run/web.log`.
This is the same command and working directory as `pnpm dev`. The PID is recorded in `.run/web.pid`, and
`make stop` still stops the server and its child processes. The web server keeps running after the shell that
started it exits.

### Accurate unavailable states
If the BFF cannot reach the backend (for example, the web server was started without its auth settings), the UI no
longer shows setting names or zeros as if they were real values:
- model names show `unavailable` (`…` while loading), and copy filled from the model settings reads
  `LLM_MODEL (unavailable)` / `EMBEDDING_MODEL (unavailable)`;
- the overview counters (open cases, running threads, pending approvals, knowledge chunks) show `—` until the
  backend answers. Real zeros still show as `0`.

### Corrected startup documentation
`apps/web/README.md` and `docs/development/DEVELOPMENT.md` now say to start the stack with `make dev` (or
`scripts/start.sh`), not a bare `pnpm dev`. Next.js only reads `.env*` files from `apps/web`, so a bare `pnpm dev`
runs without auth settings and the BFF fails closed. The docs describe the allowlist and where to extend it, and a
troubleshooting entry covers the `web authentication is not configured` symptom. `SECURITY.md` has a new
threat-model row for the web server process.

## Tests
- `tests/security/test_web_process_env.py`: allowlist and denylist, plus the real launch path with a stand-in
  `next`. It checks the detached session, the `apps/web` working directory, an allowlisted environment in the
  server and its child process, and that no secret value from the test environment leaks.
- `apps/web/tests/unavailable-states.test.tsx`: model name while loading, on failure and on success; overview
  counters when the backend is unavailable and when it answers.

## Upgrading
If a web server is already running on :3000 from an earlier launcher or a bare `pnpm dev`, stop it (`make stop`)
and run `make dev` again. `make dev` does not replace a server that is already listening, so the old process keeps
its old environment until it is restarted.
