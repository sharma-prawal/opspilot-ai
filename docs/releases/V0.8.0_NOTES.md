# OpsPilot AI v0.8.0 — Visual Experience 2.0

An approved frontend and branding release on top of v0.7.1. Both Visual Experience 2.0
commits (`0a734f3`, `31aea99`) are integrated without changing backend investigation
logic, safety enforcement, models, adapters, database schemas or startup behavior.

## What's changed

- **Original identity:** evidence-convergence logo, light/dark vector wordmarks,
  symbol, app icon, favicon and reusable PNG exports. The approved ivory-and-ink
  Incident Forensics Lab direction is retained.
- **Less default text:** compact three-mode intake, operational status strip,
  searchable incident roster, concise facts and expandable technical depth.
- **Action-first workbench:** pending simulator decisions precede forensic detail.
  Review links reveal Analysis and focus the actual approval control. Exact
  parameters, rationale, blocked reasons and human approval boundaries remain intact.
- **Evidence visualizations:** persisted metric summary comparisons with units and
  provenance, source/evidence composition, source chronology, ranked hypotheses and
  selectable source-linked evidence relationships. Workflow chronology remains
  separate from service observations; no time series is invented from event counts.
- **Responsive and accessible:** keyboard focus follows selected evidence, mobile
  decision controls are directly reachable, charts have larger labels, and diagrams
  and comparison tables retain accessible scrolling and textual alternatives.
- **Simpler integrations:** compact implemented-source rows, per-provider connection
  tests/configuration, and secondary capability comparisons/technical contracts.
  Loki and Prometheus remain implemented; Datadog, Azure Monitor and CloudWatch remain
  planned. No connector was added.
- **Progressive safety presentation:** the five-stage approval boundary stays prominent;
  seven short gate summaries expand to the full criteria. HMAC authorizes individual
  actions; recovery is checked against observations, not cryptographically certified.

## Preserved behavior and upgrade

The v0.7.1 web environment allowlist, detached startup and accurate unavailable states
are included unchanged. Existing authentication, source provenance, report downloads,
local Ollama inference and simulator-only approved execution are retained. Uploaded
and connected investigations remain read-only. No migration, credential change,
model download or data reset is required. Existing runtime instances are not changed
by publishing this release; use the normal launcher workflow when choosing to upgrade.

## Verification and evidence

The integrated code passed `make lint`, `make test` (396 Python and 68 frontend tests;
three opt-in live-model tests skipped), and the production frontend build. All seven
affected live Playwright journeys passed on `opspilot_test`, as did the 16-check
production-browser smoke suite. The latter checks desktop/mobile approval focus,
evidence navigation, connector disclosures, gate details, unavailable states and
original-symbol legibility at 16/24/32 px on light and dark backgrounds.

[Current implementation captures](../images/visual-experience-2/refinement/README.md)
use visibly labeled synthetic fixtures. They establish rendered behavior and layout,
not live operational state. Text-density and usability improvements are design judgments;
no percentage reduction, operator-performance gain, calibrated confidence or new model
evaluation result is claimed. Metric evidence contains summaries rather than a full
historical series. The primary interface remains light, with dark branding exports.

See the [design notes](../design/VISUAL_EXPERIENCE_2.md), [brand guide](../design/BRAND.md)
and [README](../../README.md) for details. All existing local-first and single-execution-owner
limitations remain applicable.
