# OpsPilot AI v0.12.0 — Investigation Experience Refinement

25 November 2026. Consolidates UI Pass A and Pass B on the existing Incident Forensics Lab interface.

This release makes saved incident state, authorization history, evidence limits and investigation context
more explicit. It improves how an operator finds and verifies an investigation; it does **not** establish
RCA diagnostic accuracy or calibrate model confidence. No agent/model evaluation was run for this release.

## Pass A — correctness and responsive usability

- **Persisted authorization history.** Completed or failed execution no longer hides the original authorization.
  The UI reads identity/hash-matched approval decisions with the original actor and aware timestamp, independently
  of execution and recovery. Missing or invalid legacy history remains unknown; success never establishes approval.
  The additive `decision_history` DTO field carries this whitelisted metadata through the BFF's existing blanket
  credential redaction. Direct API clients retain `authorization`; no redaction exemption or enforcement change.
- **Complete-history incident search.** The roster searches reference, title and service across the stored history,
  with server-side source/state filters, explicit totals and pagination. Literal `%`, `_` and SQL-like input remain
  search text. Ordering is stable by `(created_at DESC, id DESC)`; count/page share one database snapshot, including
  empty and out-of-range pages. Overview source counts describe all stored incidents.
- **Historical metric wording.** Saved baseline/extreme/latest values are labelled as collected evidence, not live
  health or a time series. Evidence observation time and unavailable latest-sample time stay distinct. Simulator
  post-action verification is a separate record; an external snapshot never establishes current recovery.
- **Mobile/tablet controls and navigation.** Roster filters and simulator controls remain within the viewport, with
  horizontal scrolling contained to the data table. The navigation disclosure exposes routes and account controls;
  Escape restores focus. Architecture pointer, Enter and Space synchronize selection, inspector and edge emphasis,
  with visible keyboard focus.

## Pass B — investigation workbench

- **Decision-first hierarchy.** Compact service/incident-state/source/investigation context, evidence window and
  saved-snapshot timing precede a prominent leading hypothesis. Model/start metadata and completed exact-action
  history disclose when needed; pending simulator action review stays prominent. RCA export is in the header.
- **Contextual evidence inspection.** Supporting and contradicting references, collected records, charts and
  source chronology select the same inspector without requiring a tab change. Hypothesis context remains beside
  the inspector on desktop and above it on tablet/mobile. Exact source IDs/references, service/resource identity,
  original observations, separately labelled timestamps, raw data and citation metadata remain available.
- **Accurate availability counts.** Counts distinguish unique model citations from accessible and unavailable
  records: for example, `3 cited supports (2 accessible · 1 unavailable)`. Both supports and contradictions use
  actual returned evidence IDs; missing references remain selectable and explicitly unavailable. No evidence or
  model output is fabricated or rewritten.
- **Coverage and uncertainty.** A short limits row leads to collected records, reported gaps and saved provider
  provenance. Collected, empty, partial/truncated, unavailable and not-attempted queries remain distinct. Azure's
  “No accessible matching records — access/coverage not independently verified” is preserved. Missing deployment
  history stays unknown; a log change observation does not establish complete history or causality. Hypothesis
  warnings stay beside the claim; summary warnings disclose with the unchanged original summary. Confidence
  remains explicitly model-assigned and uncalibrated.
- **Mode-specific decisions.** Simulator proposal, safety check, authorization, execution and verification are
  separate stages using the existing controls. Uploaded/connected investigations remain read-only: suggested
  actions are not executed, and external recovery is unverified. Selecting saved evidence does not query a provider.
- **Keyboard and responsive behavior.** Native citation buttons support Enter/Space; selection focuses the
  inspector and announces the exact ID/relationship. Tab reaches Close; Escape/Close returns to the originating
  control, or the selected hypothesis when that control has disappeared. Repeated selection still reveals the
  inspector. At narrow widths it stacks without an overlay, focus trap or permanent third column. Existing
  reduced-motion behavior is retained.

## API and upgrade notes

- New read-only `GET /api/v1/incidents/search`: `q` ≤200 characters, source/state filters, `limit` 1–100 (default 50),
  `offset` 0–100000. Response: `items`, `total`, `limit`, `offset`; invalid bounds return 422.
- Legacy `GET /api/v1/incidents` still returns an array, with validated `limit` 1–200. Clients needing complete
  history/totals should use `/search`. Incident overview adds `incident_sources`; action DTOs add safe history metadata.
- Pass B reuses the existing saved-dataset endpoint for upload/connector provenance; no collection/API schema change.
- **No database migration:** schema remains `0011`. No dependency, configuration, model, prompt, LangGraph workflow,
  MCP tool, connector collection, authentication or remediation safety-gate change. No new inference service.
- Release version is the Git tag. Existing internal package manifest versions are unchanged, as in prior releases.

## Remaining limitations

- Legacy authorization history may remain unknown when a valid persisted decision cannot be matched.
- Some latest-sample timestamps are unavailable. Saved observations, historical incident state and model wording
  do not establish current health, verified cause or external recovery.
- Offset pages may shift during concurrent writes despite stable ordering. Large-history performance has not
  been benchmarked for this release.
- Keyboard, representative contrast, reduced motion and the requested responsive widths were checked; full
  screen-reader/WCAG certification, physical-touch and exhaustive cross-browser/dark-mode verification were not performed.
- Connected-provider provenance and deterministic claim-warning scenarios were verified synthetically, not against
  representative saved production cases. The live activation used existing simulator/upload records. No naturally
  missing saved citation was found; a browser-local failed read exercised unavailable data without modifying records.
- **AWS CloudWatch, Azure Monitor and Datadog live-account compatibility remains unverified.** No real account or
  provider query was used for this release. Existing connector limits and provider-specific access uncertainty remain.
- Deterministic claim warnings are heuristic safeguards. The original model output can still be wrong, and these UI
  improvements do not demonstrate better diagnostic accuracy, remediation quality or operator-performance metrics.
