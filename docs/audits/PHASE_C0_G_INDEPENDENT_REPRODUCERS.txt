C0-G independent release-gate audit programs (no application changes).

Original programs are preserved in PHASE_C0_F_INDEPENDENT_REPRODUCERS.txt and PHASE_C0_INDEPENDENT_REPRODUCERS.txt. Extracted programs were run byte-for-byte. The exact PostgreSQL program exits at its duplicate-cancel cleanup with ConflictError after confirming skipped_terminal=1; a copy suppressing only that cleanup call completes R5. No probe logic or database guard was changed.

These three additional programs exercise only opspilot_test, verify SQL database identity, and must run SEQUENTIALLY with exclusive test-DB access. They run no local LLM inference or approved remediation. The startup-loss program creates two separate test investigations, waits for approval pause, and cancels them; checkpoints are retained. The ingestion program uses only a UUID-named audit source and retires it (no deletion). The process program uses ephemeral loopback ports and scratch reload files, and terminates only its own child processes / owner sessions. Never run against opspilot or alongside Python/E2E tests.

Copy each program to the specified /private/tmp path and execute from the repository root with the existing .venv. For the first two:
rtk proxy env PYTHONPATH=. PYTHONDONTWRITEBYTECODE=1 .venv/bin/python /private/tmp/<name>.py
For process checks:
rtk proxy env PYTHONDONTWRITEBYTECODE=1 .venv/bin/python /private/tmp/c0g_process_checks.py

The ownership probe accelerates the configured watchdog to 0.1 seconds and gates gateway setup. Its on_owner_lost hook only signals the barrier; it adds no suspension or exit behavior, matching the default CLI/evaluation paths. Both independent database sessions run in one OS process; separate Uvicorn process exclusion is exercised in the third program. The ingestion probe gates deterministic embedding and reranking to control a valid concurrency schedule through the real ingestion/storage/retrieval implementations. Two scratch paths represent two snapshots of one logical source.
