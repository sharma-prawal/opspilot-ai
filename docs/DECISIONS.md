# Decision Log

Architecture-level decisions have ADRs in `docs/adr/`. This log records the smaller engineering
decisions made during implementation, with the evidence behind them. Newest last.

| # | Date | Decision | Rationale / evidence |
|---|---|---|---|
| D1 | 2026-11-04 | Use Colima + Homebrew Docker CLI 29.9 / docker-compose 5.7; leave Docker Desktop 4.22 untouched | Desktop was never initialised, daemon down, CLI API 1.43 too old; Colima gives a capped VM (4 CPU/4 GiB/30 GiB). |
| D2 | 2026-11-04 | Scripts call standalone `docker-compose`, not `docker compose` | `~/.docker/cli-plugins` resolves to Desktop's stale v2.20 plugin; avoids editing the user's Docker config. |
| D3 | 2026-11-04 | One Python distribution, multiple top-level packages under the suggested monorepo dirs (hatch `packages` + `dev-mode-dirs`), one `uv.lock` | Clear boundaries without 7 pyprojects; boundaries enforced by import-linter instead. |
| D4 | 2026-11-04 | Python 3.13 (uv-managed), pinned `.python-version` | All dependencies support it; `requires-python >=3.12,<3.14`. |
| D5 | 2026-11-04 | `EMBEDDING_DIMENSIONS=1024` | Measured from live `/api/embed`, not assumed; ingestion rejects any vector of a different length. |
| D6 | 2026-11-04 | LangGraph checkpoint tables in schema `langgraph` via `search_path`; `setup()` only in `opspilot migrate` | Isolation from app schemas; no DDL on application start. |
| D7 | 2026-11-04 | Explicit `JsonPlusSerializer(allowed_msgpack_modules=None)` + JSON-only state | Strict deserialisation independent of import-time env; documented by langgraph-checkpoint security notes. |
| D8 | 2026-11-04 | Approval = DB compare-and-set **and** HMAC token (action_id + params_hash, TTL) verified by the action server, which executes the *persisted* parameters | Keeps `ops` single-writer, gives defence in depth, makes replay impossible (idempotency ledger `sim.action_executions`). |
| D9 | 2026-11-04 | Two MCP servers (read vs action) over stdio, one long-lived session each per API process | Write tools are not even visible to investigation nodes; no network port; ~1–2 s start-up once. |
| D10 | 2026-11-04 | Deterministic analysis (onset detection, log clustering, change correlation) in code; LLM for plan + RCA only | Small model is unreliable with numbers; 2 LLM calls per run keep latency ~25 s. |
| D11 | 2026-11-04 | No heuristic fallback for RCA | If the model fails, the investigation fails visibly with evidence retained, rather than masking model failure. |
| D12 | 2026-11-04 | `inline_schema` keeps a *property* named `title` | Bug found in first live run: stripping all `title` keys removed `hypotheses[].title` from the decoding grammar → 3 failed attempts. Regression test added. |
| D13 | 2026-11-04 | Category definitions in prompts; triage declared provisional | Model labelled a schema migration `configuration_error` and the alert-only triage `resource_exhaustion` (0.8). After the change: `deployment_regression` / `unknown` (0.3). |
| D14 | 2026-11-04 | `knowledge` capability is policy-mandated | Evaluation run showed `required_tools_used_rate = 0.0`: after a prompt edit the model stopped selecting knowledge, so RAG never ran. Now added by policy (noted in `plan.notes`); re-measured 1.0. |
| D15 | 2026-11-04 | Dispatch by data dependency: telemetry → dependencies → changes → knowledge | With plan order, `changes` ran before `dependencies` and scored the culprit migration 0.39; with dependency order it scores 1.00. |
| D16 | 2026-11-04 | Persist the partial result when the graph pauses | The UI showed "collecting evidence" at approval time; reviewers must see hypotheses before deciding. |
| D17 | 2026-11-04 | Log `contains` search uses escaped `ILIKE`, not full-text | PostgreSQL's parser tokenises `psycopg.errors.UndefinedColumn` as one host-like lexeme, so `UndefinedColumn` matched 0 rows (found by MCP protocol test). |
| D18 | 2026-11-04 | Keep RRF hybrid as default but **do not** claim it is better | Benchmark: hybrid nDCG@10 0.901 vs vector 0.932 (keyword 0.820); hybrid best on Recall@5 and ties on exact-token queries. Tuning RRF weights on a 30-question self-authored set would overfit; revisit with a held-out set or a reranker. |
| D19 | 2026-11-04 | Web UI talks only to a same-origin BFF route that injects the operator token server-side, with a path allowlist | Token never reaches the browser; traversal and non-allowlisted paths return 404 (verified). |
| D20 | 2026-11-04 | TanStack Query polling (2–5 s) instead of SSE for now | Simple, sufficient for one operator; SSE can be added on top of `workflow_events`. |
| D21 | 2026-11-04 | Playwright clicks that trigger client-side navigations use `noWaitAfter` + explicit `waitForURL` | Playwright's implicit post-click navigation wait never settled with Next 16 prefetching (reproduced in isolation; navigation itself committed fine). |
| D22 | 2026-11-04 | Evaluation has its own entry point (`opspilot-eval`) | import-linter flagged `opspilot_api.cli → opspilot_eval`; fixed the dependency instead of weakening the contract. |
| D23 | 2026-11-04 | Line length 120, `ruff format` as formatter | Consistent style across the codebase; formatter applied once to everything. |
| D24 | 2026-11-04 | Multi-step remediation plans: graph loop `propose → await_approval → execute → advance → …`; each step separately approved, with its own action ID and HMAC token | INC-003 needs containment → resolution → recovery; a single action cannot express "pausing is not resolving". This changes the graph shape (ADR-006's approval contract is unchanged per step). |
| D25 | 2026-11-04 | Plan validation is code, not prompt: impact-ended gate, rollback correlation ≥ 0.3, ambiguity gate (rival within 0.15), causal-consistency gate (errors blamed on an unchanged unhealthy dependency), capacity gate (≤ 90% of usable connections, ≤ 2× per step), abnormality required for restart/pause | First live pass: the model rolled back unrelated deployments in all three negative scenarios (NEG-001/002/003) and proposed a pool increase to 345 connections on a 200-connection DB (INC-002). After the gates: no action executed in any negative case; the unsafe increase was blocked. |
| D26 | 2026-11-04 | Ongoing impact computed from evidence (unrecovered anomaly on the alerting service), not taken from the model | The model reported `impact_ongoing=false` for INC-001 while the 5xx ratio was 38%. |
| D27 | 2026-11-04 | Canonical plan order containment → resolution → recovery; restart/pool-scale dropped when a resolution step exists; policy appends `resume_consumer` for any paused consumer (still separately approved) | The model appended a speculative restart after the INC-001 rollback, and omitted resume in INC-003 (consumer stayed paused → not recovered). |
| D28 | 2026-11-04 | Onset thresholds require a material absolute change and ≥ 4σ of baseline noise | Zero-median count metrics (retries 0/1/2 per min) produced a false onset 20 min early, which zeroed the culprit's correlation in INC-003. Regression test added. |
| D29 | 2026-11-04 | Explicit outcomes (`mitigated`, `no_action_required`, `escalated`, `proposal_blocked`, `inconclusive`, `remediation_rejected`, `approval_expired`, `not_recovered`, `remediation_failed`, `failed`) with `escalate` flag; incident status derived from outcome | Negative cases must end with an accurate report, not a forced remediation. |
| D30 | 2026-11-04 | Approval requests expire after `APPROVAL_REQUEST_TTL_SECONDS` (default 1 h): checked at decision time and by a 60 s sweeper; the run resumes into the report path | Pending approvals must not stay actionable indefinitely. |
| D31 | 2026-11-04 | Hybrid retrieval degrades to keyword-only (with a recorded warning) when embeddings are unavailable; vector-only returns 503 | Found during the release audit: CI would have failed without Ollama, and a model outage broke knowledge search entirely. |
| D32 | 2026-11-04 | INC-001's legacy generator keeps its byte-identical logs/metrics; new data (datastore snapshots) uses a separate RNG stream | Preserves the published INC-001 dataset and its determinism test. |
| D33 | 2026-11-04 | Phase C0 works from the Codex audit of `9ec857c` as evidence, not truth: each finding is reproduced on unmodified code (or marked as verified by inspection) before it is fixed, and recorded in `docs/audits/PHASE_C0_REMEDIATION.md` | Brief requirement. The audit is preserved verbatim. Three findings were worse than stated (O: `.env` read by children; H: dispatcher would resume a cancelled workflow; F: an approvable action at confidence 0.1). |
| D34 | 2026-11-04 | BFF authenticates with an explicit local sign-in (passphrase → HMAC session cookie, CSRF, roles) and the backend requires the bearer token on every POST | H1: the proxy attached the operator credential to any same-origin POST. Origin checks alone are not authentication. OIDC remains planned. |
| D35 | 2026-11-04 | Impact is tri-state (`ongoing/recovered/unknown`); `unknown` blocks proposals and escalates; explicit escalation outranks recovery | H2: missing telemetry resolved an unhealthy incident as `no_action_required`. |
| D36 | 2026-11-04 | Transactional outbox for decisions, at-least-once delivery, token minted at delivery, startup reconciliation; exactly-once *effects* via idempotency only | H3: a crash between decision commit and resume stranded the investigation. Distributed exactly-once delivery is not claimed. |
| D37 | 2026-11-04 | Verification checks every required condition or reports `not_checked` against an explicit budget; metric-specific health semantics; action postconditions | H4: `targets[:4]` silently skipped the fifth anomaly and reported recovery. |
| D38 | 2026-11-04 | One key-based redaction policy applied at every output boundary; legacy rows sanitised only by an explicit `--apply`; checkpoint history counted, never rewritten | E: 58 dev rows held verbatim approval tokens. Rewriting serialized checkpoints risks corrupting resumable runs. |
| D39 | 2026-11-04 | Explicit uncertainty policy withholds validated plans (low confidence, escalation, competing hypotheses with disjoint evidence, exhausted budget); no operator override in this phase | F. An override needs per-user identity and its own audit trail first. Thresholds were checked against the stored Phase B traces before being chosen. |
| D40 | 2026-11-04 | DB-enforced single active investigation (partial unique index; `interrupted` counts as active) plus a DB execution lease; no Idempotency-Key | G. With one active investigation per incident, a retried start returns 409 naming the existing one. |
| D41 | 2026-11-04 | The action server's `approved → executing` claim under a row lock is the non-cancellable boundary; cancel revokes `pending/approved` first and is refused after the claim | H. This is the action server's only write outside `sim`, granted at column level. |
| D42 | 2026-11-04 | Lifecycle metadata tracked separately from the content hash (no re-embed); lifecycle tiers applied before top-k truncation | I: status changes were silently skipped, and a superseded runbook ranked first. |
| D43 | 2026-11-04 | Citations are self-contained snapshots (passage, SHA-256, document version, lifecycle status, retrieval time) rather than immutable chunk-version storage | J. Snapshots cover exactly what was cited, without a retrieval-wide "current version" filter or unbounded growth. |
| D44 | 2026-11-04 | The agent-path benchmark drives the agent's own knowledge node over a real MCP gateway instead of re-implementing its parameters; the document benchmark is retained | K. By construction it cannot drift from the agent. No reranker is added: the gap is recorded for failure analysis, per the brief. |
| D45 | 2026-11-04 | Plan acceptance = ordered conformance, no undeclared extras, no forbidden *attempt*, no unsafe effect; INC-003's containment declared in ground truth | L: a forbidden restart plus the expected rollback scored acceptable. Phase B traces re-score unchanged. |
| D46 | 2026-11-04 | E2E runs only on its own stack (API :8100 forced to `opspilot_test`, web :3100 with a separate `distDir`), verified through the BFF before any mutation | N. Verified beside a running dev stack, with dev-DB row counts unchanged. |
| D47 | 2026-11-04 | MCP children get a minimal environment (no `.env`) and separate least-privilege DB roles, with fallback to the app role when unprovisioned | O. OS-level separation is recorded as the remaining gap. |
| D48 | 2026-11-04 | Embedding concurrency bound (2) and bounded admission (4 running + waiting → 429) | P. Measured: the bound costs no embedding throughput on this Mac, because Ollama serialises the work anyway. |
