# Guide for coding agents

Read `docs/PROGRESS.md` first — it is the resumable state of the project — then `docs/DECISIONS.md`.

## Ground rules

- Never run `docker system prune`, `docker volume prune`, or delete volumes/databases. `make infra-down` only stops containers.
- Never point tests at the main database; the test DB is `opspilot_test` (enforced in `tests/conftest.py`).
- Do not add cloud/paid inference. All inference goes through `opspilot_shared.llm` ports to local Ollama.
- Keep the layering contracts green (`uv run lint-imports`): `opspilot_agents` imports only ports and domain types;
  nothing imports `opspilot_eval`.
- Agents must never read `datasets/evaluation/ground_truth/` or simulator scenario internals.
- No tool may accept free-form shell, SQL or file paths. New state-changing capabilities go only into the action
  server and must require a verified approval token.
- Keep LangGraph state JSON-compatible (strict msgpack deserialization is on).
- Report numbers only from `make evaluate` output; never edit `docs/evaluation/BASELINE.md` by hand.

## Definition of done for a change

`make lint` and `make test` pass; behaviour changes to the agent are re-measured with `make evaluate`;
docs (`PROGRESS.md`, `DECISIONS.md`, architecture pages) updated when contracts or decisions change.

## Frontend

`apps/web/AGENTS.md` (generated by Next.js) applies: this is Next.js 16 with Cache Components — read the bundled
docs in `apps/web/node_modules/next/dist/docs/` before changing routing or data fetching. Runtime hooks such as
`useParams`/`usePathname` must be rendered inside `<Suspense>`.
